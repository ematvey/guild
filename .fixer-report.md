## Clippy

`cargo clippy --workspace --all-targets -- -D warnings` now passes.

Fixed, each with the smallest change the lint asked for:

- `auth_state.rs`: `map_or(true, ..)` -> `is_none_or(..)`; removed two
  `&path` borrows that the callee already dereferenced.
- `machine_link.rs`: `contains_key` + `insert` -> `entry(id).or_insert_with`.
- `agent_start.rs`: removed two `&req.body.as_slice()` borrows.
- `fs_bridge.rs`: removed a borrow from `symlink(tmp.join(..))`.
- `daemon.rs` test: gave the `fn(PathBuf, Shared) -> Pin<Box<..>>` entry
  shape a local `type Entry` alias (type_complexity).
- `tests/ws_cloud.rs`: a `loop` with one `select!` and a `break` -> one
  `select!` (never_loop).
- `tests/machine_link_idle.rs`, `tests/machine_link_dispatch.rs`: replaced
  `Session::default()` + field assignment with a struct literal plus
  `..Default::default()`.
- `tests/auth_state.rs`: removed two `.into()` conversions that were already
  `String`.

No `#[allow]` was added.

## machine_link test

`machine_link::tests::remote_context_and_prefetch_roundtrip_on_mock_hub_socket`
failed on every run (3 of 3 before the fix), so it was not flaky.

Root cause: the test set `GUILD_SKILLS_ROOT` to a temp home, and
`skills.sync_v1` honoured it. The remote-context scan did not: it called
`fs_bridge::home_dir()` directly. So the test read the real
`~/.agents/skills` of this box. That real index has enough skills to hit the
8000-byte `INDEX_BUDGET`, so `socket-demo` was cut from the index and the
assertion failed. The test's own comment already said the env var redirected
the scan, so this was a real split of one concept (the user skill home) into
two readers.

Fix: added `fs_bridge::skills_home()` as the one skill-home reader. It
returns `GUILD_SKILLS_ROOT` when set, else `home_dir()`. Both
`machine_link` skill sync and `remote_context::prepare` now use it. Production
behaviour is unchanged (env unset). The test passes 3 of 3 after the fix.

|---|---|---|

| `cargo nextest run --workspace --profile full` | 13.0 s | 241 passed, 1 skipped |
| `cargo nextest run --workspace` | 13.0 s | 241 passed, 1 skipped |

`cargo test` spends its time serially in each test binary; the longest
binaries (12.5 s lib, 10.1 s daemon) set the wall time. Nextest runs test
binaries and tests in parallel, so the same coverage finishes in 13.0 s.

The old `.config/nextest.toml` did not parse at all: it filtered on the
removed `guild-server` package. It now uses `default-filter = 'all()'` for
both profiles. This repo has no DB or external-service Rust tests, so the old
"fast" and "full" split had no members left.

## Pruning

No test was pruned. Every test above 2 s covers a behaviour that no other
test covers: the two reaper tests exercise the ordinary and the reclaiming
daemon entries; the login/sign-out variants exercise distinct identity and
session paths. Removing any of them would remove the only test of that
behaviour. The 13.0 s wall time comes from the slowest test, not from the sum
of the suite, so pruning one 2 s test would not help much.

## Recommended gate

Replace `cargo test --workspace` with:

```sh
cargo nextest run --workspace
```

Keep `cargo clippy --workspace --all-targets -- -D warnings` as the lint
gate. `--profile full` is equivalent now; scripts that already pass it stay
valid. Do not drop `--workspace`: without it nextest runs only the default
members and skips the two `codex-*` crates.
