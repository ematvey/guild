# Server test suite — speed report

## Result

- Baseline (this worktree, same machine): **49.5 s** wall, 695 passed, 40 skipped.
- Final run 1: **20.4 s** wall, 695 passed, 40 skipped.
- Final run 2: **20.6 s** wall, 695 passed, 40 skipped.
- No failures, no "too many clients", no ClickHouse auth errors in either run.

The vitest in-run numbers moved from `tests 168 s / import 22 s` to
`tests ~229 s / import ~33 s`: more workers do more total work, but the wall
time is what the user pays.

## Config changes

`apps/server/vitest.config.ts`

- `maxWorkers: 4 -> 14`. The suites are independent stacks, and the shared dev
  Postgres allows 500 connections (300 before 2026-10-22). A worker holds about
  ten connections (app pool max 5, seeding pool, notify client), so 14 workers
  hold at most ~140. The host has 48 cores.
  - 8 workers: 29-33 s, stable.
  - 12 workers: 21.9 s, stable.
  - 14 workers: 20.2-20.7 s, stable across four runs.
  - 16 workers: 20.2 s but one or two timeouts (the M6 SPA test at 5 s, and a
    database-cleanup hook). 14 is the highest clean setting.
- `pool: "forks"`, `fileParallelism`, `minWorkers` stay as they were. Forks
  keep the event loop, undici pool and timers isolated per suite file.

## Test changes

No test was deleted. No assertion was weakened.

### ClickHouse auth noise (test-only)

Root cause: the harnesses call `loadConfig({...})` with an explicit env
object. That object does not include `process.env`, so
`GUILD_CLICKHOUSE_USER/PASSWORD` were always empty and the skills runtime's
`ensureSkillReadsTable` logged "Authentication failed" on every app start.

- `test/platform/s3-creds.ts` now also exposes `testClickhouseUser()` and
  `testClickhousePassword()`, read from the environment then the gitignored
  `deploy/compose/config.env`.
- The M1/M5/M6/M7 harnesses pass those two values into `loadConfig`.
- The DDL is `CREATE TABLE IF NOT EXISTS` on the `guild` database, where
  `skill_reads` already exists, so it is a no-op. Production ClickHouse code is
  untouched.

### Races that only appear at higher parallelism

These tests read state once, immediately after an async event. The read was
racing the server's post-commit write of `generating=false` (or the presence
slot clear). Each now polls the same condition with a short interval, then
keeps the original assertion:

- `test/ws-feed.test.ts` "the HTTP thread list agrees with the hub": poll
  `machine_online === false` after the socket closes.
- `test/worker-mode.test.ts` "admits and completes a turn through a forked
  worker" and "killing one chat's worker mid-turn...": poll until the listed
  chats show `generating=false`.
- `test/supervisor.test.ts` "a storage fault mid-turn reopens the session":
  same poll.

### Cleanup timeout

- `test/platform/platform-migrations.test.ts`: the `afterAll` that drops the
  disposable databases gets a 60 s timeout. Under 14 concurrent suites the
  default 10 s hook timeout was too short for `DROP DATABASE ... WITH (FORCE)`
  retries. This is cleanup, not a test assertion.

## Still slow / flaky

- `worker-mode.test.ts` is the longest file (~17 s of test time, dominated by
  the two worker-kill cases at ~4.4 s). It does not set the wall time at 14
  workers.
- `user-mcp.test.ts`, `queue-recovery.test.ts`, `chats-flow.test.ts` and
  `agents/delivery.test.ts` still have ~3-4 s cases. Their time is app setup,
  real socket turns and polling of real state, not fixed sleeps.
- The M6 SPA test has a 5 s timeout and times out at 16 workers. It is clean at
  14.
- No new flakiness observed: four consecutive clean full runs at 14 workers
  (two of them with the final config).

## Local-only artifacts (gitignored, not committed)

- `deploy/compose/config.env` copied from the main checkout: the S3 and
  ClickHouse credentials the harness reads. Without it the suite cannot start.
- `apps/desktop/dist` symlinked to the main checkout's built bundle: the CORS
  test asserts the SPA shell is served from the default `../desktop/dist`.
  Without it that test gets 503. This is a build artifact, not source.

VERDICT: FASTER 49.5s -> 20.4s
