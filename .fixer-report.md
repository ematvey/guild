## Problem 1 — `scripts/check.sh`

One POSIX sh script, no new dependencies, works from any cwd (it cds to the
repo root).

Checks (names as printed):

| name | command |
| --- | --- |
| `cargo-test` | `cargo test --workspace` |
| `server-test` | `npm test --workspace apps/server` |
| `desktop-test` | `cd apps/desktop && npm test` |
| `clippy` | `cargo clippy --workspace -- -D warnings` |
| `windows` | `scripts/check-windows.sh` |
| `bindings` | `scripts/check-bindings.sh` |
| `coherence` | `npm run coherence` |

Concurrency: each check runs in a background subshell. The subshell writes
its exit code and start/end nanoseconds to a result file; the parent `wait`s
and prints one line per check (`name PASS/FAIL/SKIP seconds`). Output goes to
per-check logs; a failing check prints the last 20 lines of its log. A summary
and the total wall time follow. Exit 1 on any failure.

Ordering: `cargo test --workspace` rewrites
`crates/protocol/bindings/**` and drops the `.js` suffix. `bindings` is
therefore not started with the first batch. The script waits for the
`cargo-test` job, then starts `bindings` while the other checks keep running.

Cargo jobs share one target-dir lock, so `cargo-test`, `clippy` and `windows`
queue behind each other even when started together. The TS, desktop and
coherence checks run beside them. A comment in the script records this.

Flags:

- `--fast` — skip `cargo-test` and `server-test`. The other five checks run,
  `bindings` included.
- `--only <name>` — run exactly one check.
- `-h` / `--help`.

SKIP: `scripts/check-windows.sh` now checks
`rustup target list --installed` for `x86_64-pc-windows-gnu` and exits 2 with
a SKIP message when the target is absent. `check.sh` prints `SKIP` for exit
code 2 and does not count it as a failure.

`README.md` "Build & test" now shows `scripts/check.sh` as the one gate, with
the individual commands kept below it.
